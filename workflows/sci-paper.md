# Workflow: sci-paper — 从零到一篇 SCI 论文初稿

<invocation>
$ARGUMENTS = 用户给出的题目或需求描述（可为空）
</invocation>

> 目标：让一个**没有任何科研基础**的本科生，从一句话题目，走到一篇**可投稿的 SCI 论文初稿**。
> 用户不写代码、不跑统计、不找文献——这些由你用套件里的子技能全包。
> 你唯一的责任是：**每一步都用人话讲清楚，并且绝不编造任何文献、数据或数字。**

---

## 0. 六条铁律（违反任何一条，这条工作流即失败）

| # | 铁律 | 具体含义 |
|---|---|---|
| **R1** | **绝不编造文献** | 任何被引用的文献必须真实存在。引用前必须拿到可解析的 **PMID 或 DOI**，并核对标题、作者、年份、期刊与来源一致。解析不通过的一律删除，不许"补一个看起来像的"。 |
| **R2** | **绝不编造数据** | 稿子里出现的每一个数字，只能来自两个地方：(a) 检索到的真实记录；(b) 你自己运行的脚本产出的结果文件。**禁止**凭记忆写"大约 30%"、"约 1.2 倍"这类数字。 |
| **R3** | **先查证，再动笔** | 进入写作阶段之前，所有证据、数据、结论必须已经**落盘为文件**。没有文件支撑的句子不许写。 |
| **R4** | **全程留痕** | 检索式、脚本、中间数据、决策理由全部写成文件。任何一步都必须能复现。 |
| **R5** | **每步说人话** | 每个阶段结束，用固定四段模板向用户交代（见 §4）。面向的是没做过科研的人，不是同行。 |
| **R6** | **不确定就问** | 缺少会改变研究结果的选择时，停下来问用户，不要替他决定研究范围。 |

**找不到证据时，正确的说法是"我没有找到支持这一点的文献"，而不是用"一般认为"含糊过去。**

## 1. 第一步：选路线（决定后面所有阶段）

先判定用户属于哪条路线，**不要跳过这一步直接开始检索**。

| 路线 | 名称 | 需要原始数据吗 | 零基础可行性 | 典型周期 |
|---|---|---|---|---|
| **A** | 系统综述 / Meta 分析 | 不需要 | ★★★ 最推荐 | 4–10 周 |
| **B** | 叙述性综述（Narrative review） | 不需要 | ★★★ | 1–3 周 |
| **C** | 公开数据库二次分析 | 需要（但免费公开） | ★★ | 6–14 周 |

**默认推荐 A。** 理由：不需要做实验、不需要伦理审批、不需要患者数据，方法的每一步都有国际规范（PRISMA / Cochrane），本科生能完整走完，且 SCI 确实接收（如 *Medicine*、*BMJ Open*、*Frontiers* 系列）。

路线 C 的常见公开数据库（临床方向）：NHANES、MIMIC-IV、GBD、SEER、TCGA、UK Biobank（需申请）。选 C 时用户必须能接受"用别人的数据"。

> 若用户题目是"某药对某病的影响"这类**干预性问题**，A 几乎是唯一零基础可行解。
> 若题目是"某现象的研究进展"这类**宽泛描述性问题**，走 B。
> 若用户明确说"我有数据"，或题目涉及"某指标与某结局的关联"，考虑 C。

## 3. 各阶段详情

### Stage 0 — Intake 信息采集

**准入**：用户给出了题目或大致方向。

**做法**：**分轮提问，一轮最多 4 个问题。** 一次抛 20 个问题会直接把小白劝退。

#### 第 1 轮（定路线）

问这 4 个，然后停下来等回答：

1. 你是哪个专业、几年级？以前读过或写过论文吗？
2. 这篇论文有时间要求吗？（组会汇报 / 课程作业 / 毕业 / 评奖学金 / 不着急）
3. 你手上有没有数据或文献？（有数据 / 有导师给的方向 / 什么都没有，只有题目）
4. 你的目标是"完成一篇能投出去的稿子"，还是"先有一个像样的初稿"？

> 拿到答案后**明确说出你推荐的路线和理由**，让用户确认，再进第 2 轮。

#### 第 2 轮（把题目变成可研究的问题 — PICO）

小白不知道什么是 PICO。**不要只给框架，要针对他的题目给出示例答案，让他照着改。** 以「二甲双胍对 2 型糖尿病患者心血管影响」为例：

| 要素 | 问题 | 给用户的示例默认值 |
|---|---|---|
| **P** 人群 | 研究对象是谁？要不要限定年龄 / 地区 / 病程？ | 成人（≥18 岁）2 型糖尿病患者，不限地区与病程 |
| **I** 干预 | 具体用什么？单药还是联合？ | 二甲双胍（单药或含二甲双胍的方案） |
| **C** 对照 | 跟什么比？ | 安慰剂 / 常规治疗 / 其他口服降糖药 |
| **O** 结局 | 主要看什么？次要还看什么？ | 主要：MACE、心血管死亡、心梗、卒中；次要：全因死亡、HbA1c、体重、低血糖 |
| **S** 设计 | 只收 RCT？还是也包括观察性研究？ | RCT 为主，必要时纳入前瞻性队列 |
| **T** 时限 | 文献从哪年到哪年？ | 建库至检索当日 |

告诉用户：**"这些默认值我替你选了一套稳妥的，你只需要指出哪一条要改。"**

#### 第 3 轮（产出规格）

- 目标期刊或分区有想法吗？（没想法时你负责在 Stage 1 给建议）
- 需要中文版对照吗？
- 图表和正文用英文（SCI 必须英文），这个没问题吧？

**门控（sufficiency gate）—— 三条同时满足才算信息足够：**
1. PICO 六要素全部有明确取值（默认值也算，但必须经用户确认）
2. 路线已确定（A / B / C）
3. 至少一个明确的主要结局指标

**产物**：`00-brief.md`，写入研究问题、PICO 表、路线、目标期刊层次、时间要求、用户能力自评。

> 若用户中途没回答清楚，**允许再来一轮补充提问**——但每轮仍不超过 4 个问题。信息足够之前不要开始检索。

### Stage 1 — 可行性与撞车查证

**准入**：`00-brief.md` 已完成。

**做什么**：在投入大量工作前，先确认这个题目**没人做过一模一样的**。

1. 用 `unified-research-finder` 或 `pubmed-database` 检索是否已有同题的**系统综述 / Meta 分析**。
2. 用 `openalex-database` 与 `perplexity-search` 交叉确认。
3. 若已存在同题 Meta 分析，**必须告诉用户**，并给出差异化方案：
   - 换人群（如限定老年 / 某地区 / 某合并症人群）
   - 换结局（如聚焦某单个终点）
   - 加入新发表的研究（原综述检索截止 2022，现在补到 2026）
   - 换研究设计范围（原综述只收 RCT，你加入真实世界研究）

**调用**：`dispatch.py load pubmed-database`、`load openalex-database`、`load perplexity-search`、`load literature-review`

**产物**：`01-feasibility.md` — 记录：检索了什么、找到几篇同类、差异点是什么、最终确认的题目。

**门控**：能写出一句明确的**新颖性声明**。写不出来，回 Stage 0 调整题目。

---

### Stage 2 — 检索策略与文献获取

**准入**：`01-feasibility.md` 已确认题目。

**做什么**：

1. **构造检索式**：主题词（MeSH）+ 自由词（tiab），布尔逻辑组合，针对 PubMed。
   例：`(metformin[MeSH Terms] OR metformin[tiab]) AND (diabetes mellitus, type 2[MeSH Terms] OR "type 2 diabetes"[tiab]) AND (cardiovascular diseases[MeSH Terms] OR cardiovascular[tiab])`
2. **记录检索元数据**（可复现的关键）：数据库、检索日期、完整检索式、命中条数。
3. **执行检索并保存原始记录**：导出 PMID / 标题 / 作者 / 期刊 / 年份 / 摘要 / DOI。

**调用**：`dispatch.py load unified-research-finder`（**首选**：PubMed 官方 E-utilities + Google 学术镜像，直接返回真实 PMID / DOI / 影响因子）、`load pubmed-database`（MeSH 主题词与检索式细节）、`load literature-review`（PRISMA 流程）、`load openalex-database`（补充）

**产物**：`02-search-strategy.md`（检索式与元数据）、`02-records.csv`（原始记录）

**门控**：检索式完整记录 + 记录数 > 0。**没有原始记录文件，不许进入筛选阶段。**
**铁律**：检索结果只能来自 `unified-research-finder` 的脚本真实响应。**找不到就是找不到，绝不编造** PMID、标题、引用数或下载链接。

---

### Stage 3 — 筛选（PRISMA）

**路线 A 完整执行；路线 B 只做简化筛选；路线 C 跳过。**

**做什么**：

1. **去重**（按 DOI / PMID / 标题+第一作者+年份）
2. **标题摘要筛**：按事先写好的纳入 / 排除标准
3. **全文筛**：逐篇确认
4. **绘制 PRISMA 流程数据**：识别数 → 去重后 → 标题摘要筛排除数 → 全文评估数 → 全文排除数（分理由）→ 最终纳入数

**关键要求**：纳入与排除标准必须在筛选**之前**写定，且每条排除都要有理由记录。**筛查过程中不许偷偷改标准**——如果标准确实不合理，明说"我要调整标准并重筛"，让用户知道。

**调用**：`dispatch.py load literature-review`、`load scientific-critical-thinking`

**产物**：`03-screening.csv`（每篇的判定与理由）、`03-prisma.md`（流程数据）

**门控**：最终纳入篇数确定，且每篇排除都有理由。

---

### Stage 4 — 数据提取与质量评价

**路线 A 执行；路线 C 改为"数据清洗"；路线 B 跳过。**

**做什么**：

1. **提取表**：每篇纳入研究提取——第一作者 / 年份 / 国家 / 设计 / 样本量 / 人群特征 / 干预与剂量 / 对照 / 随访时长 / 结局事件数 / 效应量与 95%CI。
2. **偏倚风险评价**：
   - RCT → Cochrane RoB 2（随机化、偏离、缺失数据、结局测量、结果选择性报告）
   - 观察性 → Newcastle-Ottawa Scale
   - 证据分级 → GRADE

**产物**：`04-extraction.csv`、`04-rob.csv`

**门控**：纳入的每一篇都在提取表中有一行，且偏倚评价无缺失项。

---

### Stage 5 — 统计分析

**路线 A（Meta 分析）执行；路线 C 改为回归 / 生存分析；路线 B 跳过。**

**做什么**（路线 A）：

1. **选效应量**：二分类用 RR / OR，连续变量用 MD / SMD
2. **合并**：固定效应 vs 随机效应（依据异质性选，并说明理由）
3. **异质性**：I²、τ²、Cochran Q
4. **亚组分析**：按人群 / 剂量 / 随访时长 / 研究设计
5. **敏感性分析**：逐一剔除法
6. **发表偏倚**：漏斗图 + Egger 检验（纳入 ≥10 篇时）

**铁律 R2 在这里最容易被违反。** 所有结果必须由**实际运行的 Python 脚本**产出（statsmodels / scipy），结果写入 JSON。**不许凭经验说"合并 RR 大约 0.85"。**

**调用**：`dispatch.py load statistical-analysis`（选检验、效应量、报告格式）、`load scientific-critical-thinking`（GRADE、Cochrane RoB）、`load statsmodels` / `load scipy` 相关

**产物**：`05-analysis.py`（可复现脚本）、`05-results.json`（脚本输出）、`05-results.md`（结果的人话解读）

**门控**：每个进稿的数字都能在 `05-results.json` 中找到；脚本可重跑得到同样结果。

---

### Stage 6 — 图表制作

**准入**：Stage 5 结果已落盘。

**做什么**：

- **PRISMA 流程图**（必须有，系统综述的硬性要求）
- **森林图**（Meta 分析主图）
- **漏斗图**（发表偏倚）
- 结果表格：纳入研究特征表（Table 1）、结果汇总表

**铁律**：图必须由数据文件**程序化生成**（matplotlib / plotly），导出 300 dpi、TIFF 或 PNG。**不许"描述一下图长什么样"了事。**

**调用**：`dispatch.py load meta-analysis-figures`（**首选**：森林图 / 漏斗图 / PRISMA 2020 流程图 / 偏倚风险红绿灯，吃 CSV 或计数直接出图，并内置数值一致性校验）、`load matplotlib`（其余自定义图）、`load seaborn`、`load scientific-schematics`（机制示意图）

**产物**：`figures/fig1-prisma.png`、`figures/fig2-forest.png`、`figures/fig3-funnel.png` 等

**门控**：每张图都有对应的生成脚本，且图形与数据一致。

---

### Stage 7 — 英文稿撰写

**准入**：Stage 1–6 全部产物齐备。

**做什么**：按 **IMRaD** 结构写，**全文用完整段落，不用要点列表**（学术写作规范）。

| 部分 | 要点 |
|---|---|
| Title | 含研究设计（如 "a systematic review and meta-analysis"） |
| Abstract | 结构化：Background / Methods / Results / Conclusion，含关键数字 |
| Introduction | 三段式：已知什么 → 未知什么 → 本文做什么 |
| Methods | 检索策略、纳入排除、数据提取、统计方法、注册号（PROSPERO）（系统综述需具备） |
| Results | 严格按 Stage 3–6 的产物写，每个数字可回溯 |
| Discussion | 主要发现 → 与既往研究比较 → 机制解释 → 局限 → 结论 |
| References | 用 `citation-management` 生成，全部可解析 |

**每个数字都必须能从前面阶段的文件里找到出处。** 写作时若发现缺数据，**回到 Stage 5 补跑**，不许临时编。

**调用**：`dispatch.py load scientific-writing`（IMRaD 与段落式写作）、`load citation-management`（BibTeX、DOI/PMID 校验）、`load literature-review`

**产物**：`07-manuscript.md`、`07-references.bib`

**门控**：无未填充占位符；每个数字可回溯；所有引用可解析。

---

### Stage 8 — 反造假与质量审计

**这一步是整条工作流的安全阀，不许省略。**

**做什么**（逐条核验，写成清单）：

1. **引用核验**：每条参考文献的 DOI/PMID 能否解析？标题作者年份是否与数据库一致？（`citation-management` 批量验证）
2. **数字核验**：稿中每个数字 vs `05-results.json` / `04-extraction.csv` 逐一对齐
3. **主张核验**：每个结论句是否有证据支撑？有无超出证据强度的表述？
4. **方法学自查**：按 PRISMA 2020 清单逐项打勾；统计方法是否恰当；偏倚是否充分讨论
5. **模拟同行评审**：让 `peer-review` 扮演审稿人挑毛病

**调用**：`dispatch.py load sources`（claim-level 溯源审计）、`load verify`（真跑检查，报告 pass/fail/未测）、`load peer-review`、`load scholar-evaluation`

**产物**：`08-audit.md` — 逐项结论 + 未通过项 + 修正记录

**门控**：**引用解析率 100%**；数字不一致项已全部修正；无"未测"项被隐去。

> 任何一项不通过，回到对应阶段修正，不许"先这样"。**发现编造内容必须删除并在审计文件中记录。**

---

### Stage 9 — 投稿准备

**做什么**：

1. 依据主题、影响因子区间、审稿周期、版面费，推荐 3 个候选期刊（含理由与风险）
2. 按目标期刊格式要求排版（参考文献格式、图表位置、字数限制）
3. 撰写 Cover Letter
4. 明确告知：**初稿 ≠ 可投**。仍需原作者通读、补充临床背景、按期刊要求调整

**调用**：`dispatch.py load venue-templates`（期刊/会议模板）、`load latex-posters`（如需要海报）

**产物**：`09-target-journal.md`（期刊比较与推荐）、`09-cover-letter.md`、排版后的稿件

**门控**：交付物清单完整，且已向用户说明"这是初稿、下一步需要做什么"。

## 4. 每阶段结束的固定话术（R5）

每个阶段做完，**必须**用这四段跟用户交代，不得省略：

```
【这一步做了什么】
  用两三句话说清具体动作和范围（如"在 PubMed 检索到 1873 条记录，去重后剩 1102 条"）。

【为什么必须这么做】
  解释这一步在科研规范里的作用（如"去重是为了避免同一项研究被重复计算，否则结果会偏"）。

【结果说明什么】
  这个结果对研究问题的意义，以及是否出现意外（如"检索到 3 篇同题 Meta 分析，说明题目需要调整"）。

【需要你确认的一件事】
  只提一个最关键的待决问题，给出现成选项，不要让用户自己想去。
```

## 6. 状态记录与中断恢复

- 每完成一个阶段，更新 `00-brief.md` 末尾的**进度表**（阶段 / 状态 / 产物 / 日期）。
- 用户中途离开再回来时，**先读进度表**，从第一个未完成阶段继续，不要从头重做。
- 阶段之间允许插入简短对话确认方向，但**不得跳过门控**。

## 7. 终止条件

只有同时满足以下条件，工作流才算完成：

1. Stage 0–9 全部完成（B 路线按标注简化）
2. `08-audit.md` 中引用解析率 100%，无未修正的数字不一致
3. 全部产物文件已落盘到项目目录
4. 已向用户交付：稿件全文、参考文献、图表、审计报告、目标期刊建议
5. 已明确告知用户"这是初稿"，以及后续仍需人工完成的事项（通读、补临床背景、按期刊格式调整、可能的伦理与利益冲突声明）

**中途停止时**：如实说明停在哪一阶段、缺什么，不要用"大致完成"掩盖。
